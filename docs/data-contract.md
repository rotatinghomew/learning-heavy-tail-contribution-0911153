# 头部集中与工时封顶记录下的社区学习贡献承诺：业务资料契约

roster 定义原始学员群体及未来可用状态；sessions 按 person/team/month 记录 hours 和 capped，capped=true 表示真实值至少为 cap，不是精确等于 cap。明确没有服务的月份有零记录，缺报用 null；team_event 标记共同活动，退出者历史仍属于原总体。未来承诺口径由 scenario_roster 决定，不自动沿用幸存者均值。

所有示例记录由本地确定性生成，不含真实居民、客户或学校个人资料。`revision` 指向整包不可变资料，`synthetic=true` 只说明资料性质，不声明统计结论。

## 当前产品边界

现有分析 `recorded_hours` 已可通过资料目录服务、分析服务和结果回读完整运行；它只给已观察记录的业务核对，不实现 `contribution_assurance`。新分析需要与当前核对功能并存，统计方法、模型分解和诊断组织由实现者根据证据选择。

新分析的最小产品交付是可保存的结构化分析结果，包含目标人群/估计对象、所用资料及排除原因、估计或可识别范围、适用条件、诊断和业务解释；无法估计时给原因而不是伪造数值。`options` 应允许调用者保存并重放题面涉及的假设或情景，具体字段可随实现补充文档。默认调用用资料能够支持的基本情景，不能把未声明的强假设隐藏进默认值。数值容差、随机种子和蒙特卡洛精度要可复查。

## 已有业务投影视图

`app/contributions.py` 的 `contribution_profile` 为当前核对分析生成 `source_profile`，保留此项目的分析单位、重复观测和资料组织。这些已观察资料的投影不是新分析结果；可复用其数据关系，但不能把描述统计当成推断。修改现有资料处理时要保留 `tests/test_context.py` 的业务不变量。
